# 블랙홀 구현 계획 (확정본)

확정 2026-10-25. 제품 소유자 지시 「계획서를 확정하고 구현을 시작」. 구조 설명은 `design/architecture.html`, 화면 시안은 `design/calendar-glass/prototype-glass.html`(유리 테마)·`prototype-doc.html`(공문서 테마), 리서치는 `design/calendar-glass/research.md`.

## 목표

휴대폰·데스크톱·메신저 어디서든 문장·음성·사진·파일을 **던져 두기만 하면** 이 Mac의 로컬 AI가 일정·할 일(하위 체크리스트·마감·알림)·기간·기억으로 정리한다. 정해진 시각에는 전화처럼 울리는 알람이 뜬다. 원본과 읽어 낸 글은 구글 드라이브의 「블랙홀」 폴더에 모여 옵시디언으로 검색된다.

## 확정된 결정

| 항목 | 결정 |
|---|---|
| 이름 | 블랙홀 (아이콘: 검은 판 위 일식 모양) |
| 테마 | 반투명 유리 / 공문서 보고서(개조식) 두 가지, 설정에서 선택. 출력(A4)은 공문서 양식 |

### 기본값으로 정한 것 (사용자가 다르게 말하면 바꿈)

- **학교/개인 구분**: 같은 `블랙홀/노트/` 안에서 `학교/`, `개인/` 폴더로 나눈다. 학교 자료를 개인 구글 계정에 두는 것이 학교 지침상 괜찮은지는 사용자가 확인한다.
- **확정 방식**: 일정은 모두 「가승인」으로 넣고 확정/취소를 받는다(2026-10-24 결정 유지). 할 일·기간·기억은 바로 넣고 「되돌리기」를 준다.
- **원본 처리**: 인박스 원본은 지우거나 옮기지 않고 `원본/`에 사본을 남긴다. 같은 원본은 해시로 한 번만 처리한다.

## 1단계 세부 (지금 진행)

1. 제안 JSON v2: 항목에 `subtasks`(하위 할 일), `reminders`(알림 시각 목록), 기간(`kind: PERIOD`, 여러 날)을 추가. 모델은 원문 표현만 옮기고 날짜·시각은 코드가 계산.
2. 인박스 처리기: `블랙홀/인박스/`의 새 파일 → 해시 → `원본/연/월/`에 사본 → 분석 → 노트. 같은 해시는 건너뜀. 실패는 대기열에 남아 다시 시도.
3. 옵시디언 원본 노트: `노트/{학교|개인}/연/월/날짜 제목 (해시8).md` — 머리말(해시·받은 시각·출처·상태), □/○ 체크리스트, 원문 전체, 원본 링크.
4. CLI: `blackhole-worker inbox --root 블랙홀폴더 [--once]`.
5. 검사: 단위 테스트(형식, 중복, 실패 후 재시도, 노트 내용), 필수 검사.

### 바꾼 것

- **초안 먼저, AI는 나중에.** 글이 들어오면 휴대폰과 같은 규칙 파서(`KoreanCommandParser` → TS 이식 `desktop/src/calendar/rules.ts`, 공용 정답표 `desktop/tests/fixtures/rule-cases.json` 62문장)로 날짜·시각·제목을 뽑아 바로 「초안」으로 넣는다. AI 결과가 오면 같은 항목(같은 id)을 덮어써 다듬고, 초안 없는 항목만 더한다. 항목마다 `srcKey`(인박스 작업 id = 「job-」+원본 SHA-256 앞 16자)로 초안과 AI 결과를 잇는다. 그 사이 손댄(확정·체크·하위 추가) 초안은 덮어쓰지 않고 「AI 제안 있음 · 적용/무시」만 붙인다. AI가 실패해도 초안은 남는다(「AI 분석 실패 · 규칙으로만 넣음」).
  - Mac 입력창: 넣기 → 화면 표시까지 시험에서 수 ms(jsdom), 브라우저 실측은 보고서 참조.
  - 휴대폰 → Mac: Mac이 2초마다 인박스의 `.txt`(휴대폰 문장)와 `.bhstt`(휴대폰 녹음의 기기 안 받아쓰기)를 읽어 작업기를 기다리지 않고 초안을 만든다(`DraftScan`, 읽기만). 새 파일을 보면 작업기도 바로 깨운다(15초 기다리지 않음), 업로드 대기는 5초 → 3초.
  - 휴대폰: 보내기 화면·잠금화면 적기·공유 문장·달력 화면 입력은 그 자리에서 초안을 휴대폰 달력·위젯·잠금화면에 보인다(`BlackholeDrafts`, 드라이브 왕복 없음). 녹음(보내기·잠금화면 「말하기」, 평소 PTT, 달력 「말하기」)은 기기 안 음성 인식으로 받아써서 초안을 만들고 같은 글을 `받아쓰기.bhstt`로 녹음과 함께 인박스에 보낸다. Mac 사본이 같은 작업을 다루면(`sources`) 휴대폰 초안은 빠진다. 사흘 지나도 답이 없으면 정리.
  - 휴대폰 초안에 누른 확정·체크는 동작에 `src`(작업 id)를 실어 보내, Mac이 같은 작업의 자기 항목에 적용한다(작업이 아직 안 왔으면 다음 번에).
- **휴대폰 달력이 안 따라오던 원인과 수정.** 받기 작업(`CalendarRefreshJob`)은 달력 화면이나 위젯이 등록할 때만 생겼고(앱 설치·업데이트·재부팅·앱 시작에서는 등록 안 함), 주기가 30분 + 여유 30분이라 최대 한 시간 늦었으며, 보낸 뒤 결과를 받으러 가는 길이 없었다. 기기 기록: 0.11.0 설치 14:30, 작업 등록 14:41(달력 화면을 연 때), 다음 실행 예정 +18~48분. 또 휴대폰 달력의 월 보기는 할 일을 「☐ 제목」 칩으로만 보여 마감으로 알아보기 어려웠다(③과 겹침).
  - 주기 15분(안드로이드 최소, 여유 5분). 예전 30분 등록이 남아 있으면 새 간격으로 다시 등록.
  - 앱 업데이트·재부팅(`BootReceiver`), 앱 첫 화면·보내기 화면을 열 때 등록 확인 + 바로 받기.
  - 업로드가 끝나면 15초·30초·1분·2분·5분 뒤 한 번씩 더 받기(Mac이 정리할 시간).
  - 달력 화면이 보이는 동안 30초마다 받기(전엔 60초), 새 사본·새 초안이 오면 열린 화면에 바로 알림.
- **마감이 달력에.** 마감 있는 할 일은 월·주·일에 「마감」으로 보인다. 월: `마감 [시각] 제목` + 급한 것만 표시(지남·오늘은 빨강, D-1·D-2는 기본색). 주(유리): 시각 있는 마감은 그 시각 칸에 선으로, 없으면 「기간·마감」 줄. 주(공문서): 할 일(마감) 칸에 시각과 「오늘/지남」(빨강). 일: 10분 칸에 그 시각 세로선 + 「마감 제목」, 시각 없는 마감은 시간표 위 한 줄. 마감 없이 들어온 할 일(작업기가 「오늘로 둠」)은 달력에 넣지 않고 체크리스트에만 둔다(`noDue`, 예전 자료는 검토 문구로 알아봄).
  - 기간·알림: 기간은 월 막대·주 종일 줄·일 상자, 알림은 일 시간표 점선·주 배경선으로 나오는 것을 시험으로 확인.
  - 구글 캘린더(4단계, 기본 꺼짐)를 켜면 마감 있는 할 일을 본 캘린더에 「[마감] 제목」으로 넣는다: 시각이 있으면 그 시각 30분, 없으면 그날 종일. 끝낸 것·마감 없는 것은 넣지 않는다.

### 자료 형식

- 항목에 `draft`, `srcKey`, `touched`, `suggest`(AI 제안), 할 일에 `noDue`가 더해졌다(모두 선택 칸, schemaVersion 1 그대로). 상태에 `draftedJobs`, 공유 사본에 `sources`. 예전 파일은 그대로 읽힌다.
- 인박스에 새 확장자 `.bhstt`(휴대폰 받아쓰기 JSON: `kind: "blackhole-stt"`, `sha256`(녹음), `text`, `at`). 작업기는 `.bhact`처럼 건너뛴다. 인박스 원본은 여전히 지우지 않는다.

### 확인 못 한 것

- 휴대폰 설치 후 실제 왕복 시간(보내기 → 휴대폰 초안 → Mac 초안 → AI 다듬기 → 휴대폰 갱신), 잠금 상태에서 기기 안 음성 인식이 도는지, 15분 주기 작업이 절전(Doze)에서 실제로 도는 간격.

### 같은 날 추가로 한 것 (부모 세션 전달 요청)

- **긴급: 달력.json 반복 쓰기 멈춤.** Mac 앱이 내용이 같아도 5~20초마다 「달력.json」을 다시 써 Google Drive가 CPU 190%를 쓰던 문제. 원인: 작업기가 인박스를 한 번 훑을 때마다 화면이 저장·공유를 불렀음. 이제 내용(exportedAt 빼고)이 바뀔 때만, 쓰기 사이 최소 10초, Rust 쪽도 같은 내용이면 쓰지 않음. 인박스 해시는 (경로·크기·수정 시각)으로 기억해 녹음 파일을 다시 읽지 않음. 설치 뒤 90초 동안 쓰기 0번 확인.
- **AI 꺼짐 = 대기.** 분석기 꺼짐·모델 없음·Claude 키 없음·잔액 부족·한도는 작업을 실패로 묶지 않고 10분마다 다시. 원본·작업은 지우지 않음.
- **휴대폰 홈 위젯**: 오늘 일정 + 이번 주(내일~엿새) + 마감 순 할 일, Mac 사본을 못 받았으면 그렇게 표시, 휴대폰 초안·막 누른 체크도 보임, 사본 받기·보내기·녹음 받아쓰기·잠금화면 체크 직후 다시 그림, 재부팅·업데이트 뒤 다시 그림, 누르면 블랙홀 달력. 잠금화면 위젯 분류(`keyguard`)도 내놓음(갤럭시 S25에서 되는지는 미확인: 안드로이드 16 QPR1부터 잠금화면에 모든 앱 위젯을 올린다는 보도가 있으나 One UI 8 실제 범위는 확인 못 함).
- **밝기·흐림**: 유리 테마 설정에 흐림(0~40px, 기본 26)·배경 밝기(-50~50, 기본 0) 슬라이더, Mac·휴대폰 같은 모듈, 저장됨, 공문서 테마 영향 없음. 휴대폰 위젯·잠금화면 배경은 밝기(-50~50)·판 불투명도(0~150%, 기본 100) 설정.
- **잠금화면에서 할 일 체크·메모**: 잠금화면 고정 알림([말하기][적기][사진]) 아래 묶음으로 지난·오늘·이틀 안 마감 할 일 최대 4개, 항목마다 「완료」(잠금 해제 없이). 「적기」가 메모 추가(바로 답장). 휴대폰 달력·위젯에 즉시 반영, Mac에는 기존 동작 파일 길(`*.bhact`, 원본 작업 id 함께). 설정: 잠금화면 알림에 할 일 보이기(기본 켬), 제목 가리기(기본 끔), 학교 가리기(기존 설정). 잠금 중에는 완료·적기까지만.
- **AI를 Claude API로**: `docs/local-worker.md` 「Claude API 분석」 절. 기본 `claude-haiku-5-5`, effort `low`, 구조화 출력, 캐시, 키는 macOS 키체인만, 키 없어도 초안은 동작. 실제 API 호출 시험은 하지 않음(가짜 서버만).

## 대화 패널과 「질문하면 답하기」 (2026-10-27, 사용자 지시)

### 대화 패널

- 아래 가로 입력창 + 한 줄 결과를 없애고 **창 오른쪽에 세로 대화 패널**: 위는 대화 기록, 맨 아래 입력칸·사진·말하기·보내기. 달력은 왼쪽 나머지.

### 질문하면 답하기

- 넣기인지 질문인지 규칙으로 먼저 가림: 물음표, 「뭐였지·언제·어디·뭐 있어·알려줘·했지」 등. 시각이 있는 문장에 질문 말이 섞이면(「내일 3시에 알려줘」) 「찾아볼까요, 넣을까요?」 단추 두 개.
- **로컬 색인(AI 없음, 0원)**: 일정·할 일·기간·기억·인박스 실패/검토 줄·옵시디언 노트(드라이브 「블랙홀/노트/」 .md, 앞쪽 1,200자, 수정 시각으로 캐시)·비밀 **이름**. 한국어는 형태소 분석 없이 글자 두 개씩(bigram) 역색인. 날짜 말(오늘·내일·어제·이번 주·지난주·다음 주·주말·이번 달·지난달·다음 달)은 코드로 범위를 잡고, 「…라고 했지·적어 둔」이면 넣은 날짜로, 아니면 그 일의 날짜로 거름. 「마감·할 일」 → 할 일, 「일정·약속」 → 일정, 「비번·비밀번호」 → 비밀·노트.
- 분명하면 바로 답 카드(찾은 항목·원문 위치). 다가오는 것 먼저, 지난 것은 최근 순. 「…마감 뭐 있어?」는 범위 안 목록(끝낸 할 일 빼고), 4개 넘으면 한 줄씩 빽빽하게.
- 애매(찾은 비율 45~75%)하거나 요약·판단(「요약해 줘·어떻게·왜」)이면 **찾은 줄 최대 12개만** Haiku에 짧게(`ask_records`, 같은 월 예산·사용 기록·답 캐시). 비밀은 이름만(`(값은 키체인에만)`), 비밀처럼 보이는 줄은 Rust에서 한 번 더 걸러 냄. 키가 없거나 예산을 다 쓰면 AI 없이 가까운 기록만.
- 답 카드에서 열기(그날로)·복사·완료·수정, 비밀은 「복사(Touch ID)」, 노트는 「열기」(옵시디언/기본 앱, 노트 폴더 밖은 거부).
- 빠른 입력창(⌃⌥⌘Space·오른쪽 ⌘ 두 번)도 같은 엔진: 치는 동안 질문이면 로컬 답, 아니면 가까운 기록. Enter = 질문이면 답·넣기면 넣기·애매하면 두 단추, ⇧Enter = 항상 묻기.
